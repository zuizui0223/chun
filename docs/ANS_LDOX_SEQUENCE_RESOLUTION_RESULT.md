# ANS/LDOX sequence-resolution gate

## Current question

Issue #19 requires the recurrent ANS/LDOX module to be separated into one of
three implementation states:

1. the same sequence-resolved lineage recurs across independent micro systems;
2. different paralog lineages implement the same pathway module;
3. the evidence remains at reference-family or annotation level.

The admitted clusters are:

- `CSIN_WHITE_PINK`: `CSA011508`, crosswalked to
  `TEA010322 / CSS0010687` and independently reported as a CsANS1/CsANSa-like
  source locus;
- `CRETICULATA`: three NCBI `LOC114...` reference features plus the de novo
  transcript `novel.12638`, and a later functionally validated but
  accession-free cloned `CrANS`;
- `CSASANQUA`: the unique Supplementary Table S4 K05277 candidate
  `Cao1_scaffold_14-gene-740.10`, with the published `740-F/R` qPCR assay.

## Provenance rule

The `LOC114...` identifiers are treated as mapping-reference features, not as
species-native *C. reticulata* genomic loci. Likewise, the `Cao1...` model is
an oil-Camellia reference annotation used by the *C. sasanqua* RNA-seq study,
not a demonstrated *C. sasanqua* genomic locus.

A species-native strict node is admitted only through a public accession or a
unique exact assay-to-sequence recovery that satisfies the declared length
and sequence checks. Reference-model recovery is reported separately.

## Decision boundary

Pairwise similarity can nominate a lineage, but cannot by itself establish
formal orthology, duplication age, species-native identity, repeated
macro-branch deployment, adaptation, or selection. A same-node promotion
requires independent source linkage plus near-full sequence placement and a
separate tree/context check.

The numerical result is generated by
`scripts/analyze_ans_ldox_sequence_resolution.py` and will be frozen only
after the public-data workflow completes successfully.
